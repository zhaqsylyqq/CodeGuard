# CodeGuard: запуск на сервере

Эта папка для того, кто запускает эксперименты на сервере (6 × RTX 4090, Linux, вход по SSH).
Знать проект не нужно: шаги идут по номерам, каждый шаг это одна команда.

English version of the same steps: `docs/SERVER_RUNBOOK.md`.

## Что здесь лежит

| Файл | Что делает | Когда |
|---|---|---|
| `config.env` | Все настройки: какие карты, сколько минут, 33B да/нет | поправить перед запуском |
| `1_setup.sh` | Создаёт окружение Python и ставит библиотеки | заранее, один раз |
| `2_download.sh` | Скачивает веса моделей | заранее, один раз |
| `3_check.sh` | Проверяет сервер и замеряет скорость | заранее |
| `4_smoke.sh` | Репетиция: весь план на маленькой модели | заранее |
| `5_run.sh` | Настоящий запуск в фоне | в окно |
| `6_status.sh` | Показывает, что идёт и что готово | в любой момент |
| `7_pack_results.sh` | Собирает результаты в один архив | после окна |
| `stop.sh` | Аварийная остановка, освобождает карты | если нужно |

Шаги 1–4 не занимают все видеокарты и не требуют окна. Их лучше сделать за день-два до запуска:
тогда в окно остаётся одна команда.

## Что спросить у преподавателя заранее

1. Есть ли на сервере интернет (нужны pypi.org и huggingface.co)?
2. Сколько свободного места на диске? Нужно около 100 ГБ с моделью 33B, около 40 ГБ без неё.
3. Какие карты будут свободны в окно? На сервере работает его DeepSeek, он может занимать часть карт.
4. Сколько длится окно? Можно ли оставить на ночь (8–10 часов)?
5. Можно ли сделать шаги 1–4 заранее, вне окна?
6. Есть ли на сервере Python 3.10 или новее и `tmux`?

## Шаг 0. Перенести проект на сервер

На компьютере студента (Windows, в папке CodeGuard):

```powershell
.venv\Scripts\python.exe scripts\make_colab_bundle.py --output dist\codeguard_server.zip
```

Получится один файл около 22 МБ: код и подготовленные данные. Сырых данных и весов в нём нет.
Его нужно передать на ноутбук, с которого есть SSH (флешка, Telegram, Google Drive).

На ноутбуке с SSH (вместо `user@server` свои логин и адрес):

```bash
scp codeguard_server.zip user@server:~/
ssh user@server
```

Дальше все команды выполняются на сервере:

```bash
mkdir -p ~/CodeGuard && cd ~/CodeGuard
python3 -m zipfile -e ~/codeguard_server.zip .
```

## Шаг 1. Окружение

```bash
bash server/1_setup.sh
```

В конце должно быть `CUDA available: True` и `GPUs seen: 6`. Занимает 5–10 минут.

## Шаг 2. Веса моделей

Сначала открой `server/config.env` (`nano server/config.env`) и реши про 33B:
`WITH_33B=1` скачивает и её (67 ГБ), `WITH_33B=0` пропускает.
Если на домашнем диске мало места, там же укажи `HF_HOME` на большой диск.

```bash
bash server/2_download.sh
```

Скачивается около 17 ГБ без 33B и около 84 ГБ с ней. Время зависит от интернета на сервере.
Если оборвалось, запусти ещё раз: продолжит с места остановки.

## Шаг 3. Проверка и замер скорости

```bash
nvidia-smi
```

Посмотри, какие карты свободны (колонка памяти почти пустая). Занятые убери из строки `GPUS`
в `server/config.env`. Затем:

```bash
bash server/3_check.sh
```

Должно закончиться словами `Preflight passed.` Скрипт напечатает скорость обучения и строку
`recommended: BATCH=.. ACCUM=..`. Эти два числа впиши в `server/config.env`.
Файл `logs/preflight_server.log` отправь студентам: по нему уточняется план.

## Шаг 4. Репетиция

```bash
bash server/4_smoke.sh
```

Прогоняет весь план на маленькой модели и 64 примерах. В конце у каждого запуска должно стоять `OK`.
Если есть `MISSING` или ошибка, настоящий запуск не начинать: отправь студентам папку `logs_smoke/`.

## Шаг 5. Настоящий запуск

В `server/config.env` проверь `GPUS` и поставь `WINDOW_MIN` (длина окна в минутах: 210 это 3,5 часа,
540 это ночь). Затем:

```bash
bash server/5_run.sh
```

Скрипт покажет план и запустит всё в фоне. После этого ноутбук можно закрыть, VPN может оборваться:
на сервере всё продолжит работать.

- Смотреть вживую: `tmux attach -t codeguard`. Выйти, ничего не остановив: `Ctrl-b`, затем `d`.
- Быстрый статус: `bash server/6_status.sh`.

**Что запускается.** Каждая видеокарта получает свою очередь экспериментов. Точный список и
порядок печатает `5_run.sh` перед стартом. Каждый эксперимент сам останавливает обучение по лимиту
времени, сохраняет результат и считает метрики.

## Шаг 6. Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| Один эксперимент упал | Ничего. Остальные идут дальше, в конце будет список `MISSING` |
| Сервер перезагрузился или всё остановилось | `bash server/5_run.sh` ещё раз: готовое пропустится, обучение продолжится |
| Нужно срочно освободить карты | `bash server/stop.sh`. Готовые результаты сохранятся |
| `out of memory` в логе | В `config.env` поставить `BATCH=4`, `ACCUM=8`, `EVAL_BATCH=8` и запустить `5_run.sh` снова |
| Карта занята другим процессом | Убрать её номер из `GPUS` в `config.env`, запустить `5_run.sh` снова |
| Непонятная ошибка | `bash server/6_status.sh`, затем отправить студентам файл `logs/<имя>.log` |

## Шаг 7. Забрать результаты

На сервере:

```bash
bash server/7_pack_results.sh
```

Скрипт напечатает имя архива и готовую команду `scp`. Её нужно выполнить **на ноутбуке**.
Архив передать студентам. Они распаковывают его в корень своей папки CodeGuard.

## Если на сервере нет интернета

- **Библиотеки.** На любой Linux-машине с тем же Python: `pip download -r requirements-neural.txt -d wheels`.
  Папку `wheels/` скопировать на сервер и в шаге 1 ставить так:
  `pip install --no-index --find-links wheels -r requirements-neural.txt`.
- **Веса.** Скачать на машине с интернетом (`python scripts/download_models.py`), затем скопировать
  папки `~/.cache/huggingface/hub/models--deepseek-ai--*` в то же место на сервере.

## После окна: убрать за собой

Когда студенты подтвердили, что архив получен и читается:

```bash
rm -rf ~/CodeGuard ~/codeguard_server.zip
rm -rf ~/.cache/huggingface/hub/models--deepseek-ai--deepseek-coder-*
```

Вторая строка удаляет скачанные веса. Не выполняй её, если преподаватель сам пользуется этими
моделями из того же кэша.
